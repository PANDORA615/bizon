# RFC Horror — Blender-карта и автономный генератор

В архиве находится **сама карта `RFC_Horror_Master.blend`**, генератор `generate_rfc.py`, три GLB, 54 PNG-карты материалов, адресация и отчёты проверок. Файл `.blend` открывается без установки дополнений и без скачивания текстур: все изображения упакованы внутрь. Для GLB нужен совместимый glTF-импортёр в Unity.

## Открыть карту

1. Откройте `RFC_Horror_Master.blend` в **Blender 4.3+** (проверено в 4.3.2).
2. `Numpad 0` — камера в проходе B01. `Home` — показать весь комплекс. Коллекция `RFC_ROOFS` скрыта в рабочем окне; включите её для показа крыши. На рендере крыша присутствует.
3. По умолчанию включён быстрый режим Solid с цветами материалов. Для просмотра текстур выберите **Material Preview**. Полный комплекс содержит более 20 тысяч объектов; первое открытие материалов может занять время.
4. Дневной/ночной режим: в рабочем пространстве Scripting откройте текст `RFC_Shifts.py`, задайте `SHIFT = "DAY"` или `"NIGHT"` и нажмите **Run Script**. Геометрия остаётся общей.

## Запустить Python-скрипт в Blender

Откройте `generate_rfc.py` через Scripting → Text Editor → Open, затем **Run Script**. По умолчанию создаётся полный комплекс. Если исходный `.blend` уже сохранён, результат попадёт в папку `RFC_BUILD` рядом с ним; иначе — в `Documents/RFC_BUILD` вашей системы. Скрипт не требует внешних файлов: PNG генерируются кодом.

Можно явно изменить `--output` или значение по умолчанию в `arguments()`. Повторный запуск заменяет коллекцию `RFC_HORROR`. Сторонние коллекции сохраняются; чистая стартовая сцена Blender из Cube/Camera/Light очищается.

Из терминала:

```bash
blender -b --factory-startup --python generate_rfc.py -- --output ./RFC_BUILD --mode full --export
```

Быстрый режим, с тем же масштабом и всеми этажами, но меньшим количеством рядов:

```bash
blender -b --factory-startup --python generate_rfc.py -- --output ./RFC_SMALL --mode small
```

Средняя плотность: `--mode medium`. Отдельный сектор по владельцу объекта: `--sector B01-F00-X002-Y004`. Это **частичная выгрузка**, которой также нужна общая геометрия из блока: пол, стены, перекрытия. Манифест зависимостей — `metadata/sectors.json`. Полноценный секторный стриминг не реализован.

Дополнительные кадры: `--previews`. Рендер выполняется на CPU, без необязательного OpenImageDenoise; для финальной художественной съёмки увеличьте samples и разрешение. На обычном компьютере рендер всего набора может занять несколько минут или больше.

Свой конфиг: скопируйте `config/warehouse.json`, измените значения, добавьте `--config /путь/warehouse.json`. Неизвестные поля отклоняются. Размеры блоков и координаты фиксированы в `BLOCKS` в начале скрипта, чтобы обычное изменение плотности не уменьшало масштаб.

## Состав карты

- B01: 420 × 320 × 24 м, x=0..420. Приёмка, внутренние доки, карантин, возвратная тара, КГТ, четырёхуровневый мезонин, пост охраны, раздевалка, место отдыха/выдачи заданий.
- B02: 520 × 360 × 24 м, x=440..960. Четыре уровня хранения, КГТ, грузовая башня, техническая инфраструктура.
- B03: 420 × 320 × 24 м, x=980..1400. Упаковочные столы, весы, терминалы, сортировочные рукава, накопители, доки и технологическая антресоль +6 м.
- Два соединения между каждой парой соседних блоков: основное и логистическое. Проёмы физически вырезаны сегментами стен.
- B01/B02: отметки уровней 0 / 4,8 / 9,6 / 14,4 м; четыре лестничных узла на блок. B03: два лестничных узла.
- Дневные, ночные, аварийные и рабочие группы света. Хоррор-маркеры, два логических обхода в зоне погони, безопасные комнаты.
- Полная плотность: 560 рядов на всех этажах, 42 112 секций, 168 448 ячеек. Целевые 80 секций — предел длины ряда; часть рядов укорочена на 8/16 секций для вариативности. Коридоры не сужаются.

## Текстуры

54 оригинальные бесшовные PNG 256×256: BaseColor, Roughness и Normal для 18 материалов. Бетон, окрашенный металл, оцинковка, ржавчина, дерево, картон с упаковочной лентой/этикеткой, лента конвейера, решётка с alpha, сигнальная маркировка и светящиеся панели. UV заданы в масштабе метров. Все карты сохраняются в `textures/` и упаковываются в `.blend`; GLB содержит изображения внутри бинарного файла. Пользователю разрешено использовать и изменять эти сгенерированные ассеты в своём проекте без атрибуции.

Материал решётки визуально прозрачный. Его физический пол должен оставаться **сплошным**, по `collision_proxies.json`. Alpha-материал требует отдельной проверки в выбранном Unity render pipeline.

## Данные для Unity

Координаты JSON: **метры, Blender Z-up**. У блоков указано глобальное начало; локальное положение = глобальное минус начало блока. GLB экспортируется Y-up. Базовое преобразование glTF: `(x, y, z) Blender → (x, z, -y) glTF`; конкретный импортёр Unity дополнительно учитывает левостороннюю систему. Проверьте положение контрольной точки, оси и масштаб 1 м перед сборкой навигации.

`collision_proxies.json` содержит центры, **локальные размеры ориентированного бокса** и углы Euler XYZ в радианах. Это метаданные, а не уже установленные Unity-компоненты Collider. Лестничные рампы скрыты на рендере и исключены из визуального GLB; создайте их коллайдеры из манифеста. Светильники в GLB представлены визуальной геометрией; сами источники света восстанавливаются из `lighting_groups.json`.

Крупные меши связаны между экземплярами. Нет Rigidbody и физических объектов для отдельных товаров. Адреса ячеек лежат в JSON, а не в сотнях тысяч Blender-объектов. Все ID, seed, версия и SHA256 конфига включены в метаданные.

## Что реально проверено

Смотрите `reports/` и `BUILD_VERIFICATION.json`:

- запуск генератора в Blender 4.3.2 в режимах small и full;
- связность логического графа людей, хоррор-агентов и рохли в состоянии OPEN;
- достижимость этажей при удалении каждого отдельного лестничного ребра;
- консервативная проверка горизонтальных рёбер графа по габариту агента против ориентированных боксов, преобразованных в AABB;
- уникальность адресов ячеек, целостность заголовков GLB и встроенность изображений;
- сохранение/повторное чтение `.blend`, упаковка текстур; результаты дополнительных проверок — в отдельном отчёте.

**Это статическая Blender-карта с метаданными для интеграции. Полная приёмка игрового уровня по RFC v3 не заявляется.** Unity недоступна: импорт в Unity, игровой проход, лестницы в контроллере персонажа, развороты техники, смены/AI/преследования, все состояния дверей, стриминг, LOD и FPS — `NOT_RUN` либо не реализованы. Прямолинейный граф и AABB-проверка не заменяют NavMesh и игровые тесты. Нет звуковых файлов; есть точки аудио. Послойные планы и обзорная схема приложены для проверки планировки.

Конкретный FPS не обещается. Площадь 456 000 м² — художественный масштаб из ТЗ, не строительный проект.

Для PNG-планов из метаданных приложен необязательный `tools/render_plans.py`; он использует Pillow. Сам Blender-генератор строит SVG-планы и PNG-текстуры без сторонних пакетов.

В проверенной серверной сборке нет OpenImageDenoise. В официальной Blender при финальном рендере можно включить Render Properties → Sampling → Denoise и увеличить Samples. Набор из 12 финальных кадров с высоты игрока в эту поставку не входит; соответствующий пункт отчёта — NOT_RUN.
